# Oracle Primavera P6 Professional feature inventory (with planner-facing P6 EPPM notes)

Compiled 2026-11-21 from Oracle's public documentation (P6 Professional help, user guides, importing/exporting and reporting guides for versions 20-25; P6 EPPM help; P6 Visualizer help; P6 EPPM "What's New") plus Tensix training articles where Oracle's own release notes were not fetchable. Everything is paraphrased. Where a doc set is cited by Oracle library ID: F25600/F25599 = v20, F37128/F37125 = v21, F51303/F51301 = v22, F74771/F74773 = v23, F88968/F88966 = v24, G18296/G18294 = v25, G48902/G48897 = v26.

Confidence key: **High** = the cited Oracle page was fetched and states the detail. **Medium** = detail comes from an Oracle search snippet, a TOC-level Oracle page, or a reputable training article (Tensix). **Low / unverified** = not confirmed in any fetched source.

Row convention: "Tools >", "View >", "Project >", "Enterprise >" and "Admin >" are P6 Professional menu paths. EPPM items are marked.

## Ten features Oracle's documentation presents as P6's signature strengths

1. **An explicit, configurable CPM engine**: retained logic / progress override / actual dates, longest-path or float-threshold criticality, float basis per project or across open projects, start/finish/smallest float, selectable lag calendar, open-end handling and expected-finish dates, all documented as user-set Schedule Options.
2. **Multiple float paths**: ranking the N most critical paths by total or free float to a chosen end activity, with Float Path fields for grouping (Oracle describes it as the precise alternative to Longest Path).
3. **Enterprise structure**: EPS/OBS/WBS up to 50 combined levels, project codes, portfolios and multi-project scheduling with inter-project relationships, "ideal for planners and schedulers" in Oracle's own words.
4. **Baseline management**: unlimited stored baselines, a project baseline plus three per-user comparison baselines, baseline types, and the Update Baseline utility with filters and previews.
5. **Resource and role management**: time-phased availability and multiple rates, resource curves (21 points), manual future-period buckets, cross-project usage profiles and spreadsheets, and levelling with explicit priorities and float protection.
6. **Earned value and period performance**: EV technique selectable per WBS (0/100, 50/50, milestones, custom; PF-based ETC), financial period calendars and Store Period Performance producing editable past-period actuals.
7. **Coding and customisation**: global/EPS/project activity codes (with secure codes and colours), UDFs including indicator fields, and Global Change rules with date arithmetic and functions.
8. **Layout engine and Visualizer**: filters, 20-level grouping, bars with necking and progress lines, columns, saved global/user/project layouts; Visualizer Gantt and Timescaled Logic Diagrams with command-line automation.
9. **Interoperability with owner-mandated formats**: XER and P6 XML (with baselines), Microsoft Project XML/MPX, XLSX round-trip, UN/CEFACT, IPMDAR and CPP exports.
10. **Schedule quality tooling**: Check Schedule Report (DCMA-style checks with targets and failing-activity filters), Schedule Comparison (Claim Digger), schedule logs, and progress tools (Progress Spotlight, Update Progress, Apply Actuals) that keep status consistent with the data date.

## Five things planners commonly use P6 for that smaller tools struggle with

1. **Contractual schedule exchange and delay analysis**: issuing and receiving XER / P6 XML files that carry multiple projects, baselines, codes and calendars, then running Schedule Comparison between revisions or against the baseline to evidence changes.
2. **Period-based earned value reporting**: storing period performance against financial period calendars so actuals, EV and PV are reported per period (not spread evenly) and exported in UN/CEFACT, IPMDAR or CPP formats for government and major-owner reporting.
3. **Programme-scale, multi-project scheduling**: scheduling many projects together with inter-project links and shared or per-project data dates, rolling up through the EPS with summarisation and Tracking layouts, and resolving logic with multiple float paths and longest-path criticality across mixed calendars.
4. **Cross-project resource and role capacity management**: enterprise resource pools with time-phased limits and rates, role-based planning later replaced by named resources, usage profiles across all projects, manual future-period buckets, and levelling that respects project priorities and preserved float.
5. **Audit-grade schedule quality checks**: running Check Schedule against DCMA-style targets, filtering failing activities, inspecting schedule logs for open ends and unsatisfied constraints, and applying Global Change or codes/UDFs to remediate at scale before submission.

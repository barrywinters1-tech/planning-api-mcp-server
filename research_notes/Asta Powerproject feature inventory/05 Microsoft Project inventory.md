# Microsoft Project feature inventory

Research date: 2026-11-21. Scope: Microsoft Project desktop (Project Standard / Project Professional 2016–2024 and the subscription "Project Online Desktop Client" / "Microsoft Project desktop client"), with Project Online, Project Server and Planner premium (the former Project for the web) covered at summary level where they face planners.

Method: every row was checked against a page fetched during this research (mostly support.microsoft.com and learn.microsoft.com). Descriptions are paraphrased, not copied. Confidence key:

- **High** – the English Microsoft page was fetched and the row reflects what it says.
- **Medium** – only a search snippet of the Microsoft page, or a reputable secondary source (MPUG, Microsoft Tech Community, O'Reilly/Packt training text), was available.
- **Unverified** – could not be confirmed from any fetched source; treat as a claim to check.

Context notes that matter for reading the tables:
- Project Online retires on 30 September 2026 (end of sale was 1 October 2025). Project desktop and Project Server are explicitly "not impacted".
- Project for the web and the Project/Roadmap Teams apps were retired in August 2025; their "premium plans" now live inside Microsoft Planner under the Planner Plan 1 / Planner and Project Plan 3 / Plan 5 licences.
- Office LTSC 2024 (which includes Project Professional 2024 and Project Standard 2024) "doesn't receive any new features"; Microsoft points customers who want ongoing Project desktop feature updates to the Plan 3 / Plan 5 subscriptions.

## Ten features the documentation presents as Project's signature strengths

Ranked by how prominently Microsoft's own help and product pages lead with them.

1. **Auto-scheduling engine with a transparent model (Work = Duration × Units)** – the "how Project schedules tasks behind the scenes" article is the anchor of the help library: links, constraints, calendars, task types and effort-driven scheduling all feed one calculation the user can reason about.
2. **Manual and auto scheduling in the same plan** – placeholder tasks with free-text dates for early planning, switched to auto-scheduled later; Microsoft presents this as the way to start a plan before the logic is known.
3. **Diagnostics: Task Inspector and Task Path** – the "view and track scheduling factors" pane and the driving-predecessor highlighting are sold as the way to answer "why is this task here?".
4. **Critical path controls** – critical-task formatting, a configurable slack threshold and "calculate multiple critical paths" are given their own how-to pages.
5. **Eleven baselines plus ten interim plans, Variance table and Tracking Gantt** – the baseline article is one of the longest in the set and is the backbone of the tracking guidance.
6. **Resource leveling with a fully exposed options dialog, Leveling Gantt and Team Planner** – leveling granularity, order, slack-only, splits, assignment-level adjustments and the drag-and-drop Team Planner are presented as the resource-management differentiator (Team Planner is Professional-only).
7. **Cost and earned value built in** – rate tables with effective dates, cost resources, fixed costs with accrual, and PV/EV/AC/SPI/CPI tables and the Earned Value report "for the rest of us".
8. **Custom fields with lookup tables, formulas and graphical indicators** – 130 local fields per task/resource (plus enterprise fields), rollups and icon-based indicators are pitched as the way to make any view a dashboard.
9. **Views, tables, filters, groups and the Organizer** – more than twenty built-in views, fully customizable tables/filters/groups, combination views, and the Global template for sharing them across files.
10. **Reporting and sharing: built-in graphical reports, Visual Reports to Excel/Visio, Timeline copy to PowerPoint/Outlook, PDF/XPS and Copy Picture** – Microsoft repeatedly frames Project as the planning engine whose output lands in the rest of Office.

## Five things people like about Project that construction-specific tools lack

These are inferences drawn from what Microsoft's documentation makes easy and from the sibling demand notes (`research_notes/Scheduling software customer demand/ms_project.md` and `asta_powerproject.md`), not from a user survey; treat them as hypotheses.

1. **It behaves like the rest of Office** – ribbon, Backstage, Copy/Paste into Word/PowerPoint/Outlook with live formatting, Excel-style AutoFilters, and a Timeline that drops straight into a status slide. Asta reviewers' main complaint is that programmes are "hard for non-Asta people to read"; Project's output is familiar to everyone in the business.
2. **Ubiquity and round-tripping** – .mpp is the lowest-common-denominator exchange format clients and subcontractors can open; Excel/CSV/XML import-export maps, the SharePoint tasks-list sync and the Planner Power App import all exist out of the box, and VBA plus a huge third-party add-in and training ecosystem sits on top.
3. **Microsoft 365 collaboration without extra servers** – Planner premium (Gantt, dependencies, baselines, portfolios, workload) and Planner in Teams are included in Plan 3/5 licences with Microsoft 365 identity, whereas Asta's collaboration, dashboards and API sit behind separately priced Vision cloud tiers.
4. **Agile and resource-centric views in the same file** – Task Boards and sprints (subscription client), Team Planner drag-and-drop reassignment and the usage views give non-CPM stakeholders a way in; construction CPM tools are Gantt-first.
5. **Built-in business reporting** – Visual Reports to Excel PivotCharts and Visio, the graphical report designer, Power BI/OData for Project Online and earned-value tables mean cost and status reporting needs no separate BI product; the construction tools' reporting is thinner or paid.

Counterpoint worth keeping in view (from `ms_project.md`): construction planners dislike Project's single hours-per-day factor across calendars, one relationship per task pair, unnamed baselines without saved logic, no longest-path calculation and weaker out-of-sequence progress handling. The strengths above are about reach and familiarity, not scheduling rigour.
